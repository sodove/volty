# Protocol4 SFU candidate artifact

This creates an explicit candidate, never a production cutover. Default Compose remains stock/legacy. Existing production services and dirty VPS checkout are not inputs.

1. Run `prepare-overlay.ps1 -Production -Destination <fresh-owned-directory>` against the audited source snapshot. Default mode retains the prototype race hooks; Production excludes them. `test-production-overlay.ps1` creates and checks a fresh Production destination instead. Exact source anchors/hashes reject incompatible source.
2. In that generated source, compile with the pinned Go1.26.0 toolchain and `CGO_ENABLED=0 GOOS=linux GOARCH=amd64`, using `go build -trimpath -buildvcs=false -mod=readonly -o <owned-binary> ./cmd/server`. Run the existing lease tests in that generated package. Keep toolchain/build metadata and binary SHA256. This stage does not claim bit-for-bit reproduction from a second clean toolchain build.
3. Run `prepare-image-context.ps1 -Binary <owned-binary> -ExpectedBinarySha256 <recorded-hash> -RuntimeImage livekit/livekit-server@sha256:<verified-runtime-digest> -Destination <fresh-context>`. Tags, a different binary hash, non-amd64/Linux executable or unexpected Go build metadata fail before context creation. It emits a whitelist context with only binary, manifest, build metadata, Dockerfile and ignore file; configuration/credentials are never image inputs. Build `docker build --network=none --pull=false -t <unique-task-tag> <context>` on an amd64 Docker host. The runtime digest is an operator input, not an unverified floating tag.
4. Verify transferred binary identity and record image ID. Start only a uniquely named disposable container from that image with loopback-only randomly allocated HTTP port, memory/CPU limits, read-only filesystem and a read-only copy of `probe.yaml`. Use its public disposable credentials, never production credentials. `--config /etc/volty-probe.yaml --bind 0.0.0.0` permits the container port mapping; do not publish ICE/UDP for this control probe.
5. Run `python3 probe-image.py --url http://127.0.0.1:<owned-port>`. Nine control checks require fresh readiness, protocol4/single-node/30s lease/fresh sweep/free capacity, unauthenticated denial, absent test route even with room admin, register, rejection of connected-renewal before transport, participant observation, renew, revoke and denial of re-register. This is control compatibility, not synthetic RTP, Android capture/rendering, audibility or network traversal proof.
6. Always clean up only the exact container ID after verifying its image ID; retain the candidate image/context and sanitized evidence for review. No generic container/image pruning. Coordinate backup, old backend/SFU retirement and compatible clients separately before any real deployment; see the device acceptance plan.
