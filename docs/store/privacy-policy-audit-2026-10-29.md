# Volty privacy policy: source audit

Public URL: https://sodove.ru/privacy_volty.html

Canonical replacement HTML:
`C:/Users/sodovaya/git/sodove.ru/privacy_volty.html`.
The previous server file is preserved at
`.artifacts/play-console/privacy-server-original.html` and in an operator-owned
backup outside the website root on the server.

The old policy denied personal-data storage/transmission. That claim is
retracted: current account, position-sharing, voice and navigation functions
process the data described in the new policy. The page also has Cloudflare
edge-injected scripts, so a blanket no-cookie/no-analytics assertion was removed.

## Evidence used

- Local vehicle/history/settings storage: SQLDelight repositories and
  `data/history/HistoryMediaImport.kt`; original selected media bytes are copied
  to app storage. `presentation/history/HistoryMediaPlatform.android.kt` uses
  the Android visual picker. Export repositories and `LogExporter.android.kt`
  hand exports to an Android share chooser rather than uploading them to Volty.
- Online navigation: `di/AndroidModule.kt` binds `OfflineFirstNavigationRepository`
  with `OsmNavigationRepository`, which directly queries Photon/OSRM. The existing
  store-listing draft's claim that all navigation queries go through the Volty
  server is stale and was not copied into the privacy policy.
- Local-first fallback: `domain/navigation/region/OfflineFirstNavigationRepository.kt`.
  Catalog refresh at startup: `VoltyApplication.kt`. Online map tiles, fonts and
  style resources are OpenFreeMap; requesting tiles also reveals the map area.
- Credentials: `data/social/AndroidSocialCredentialStore.kt` uses Keystore-backed
  encryption; `AndroidPushInstallationStore.kt` uses encrypted no-backup storage.
  The manifest does not disable Android app backup globally, so local data is
  not described as immune to system backup/device-transfer behavior.
- Account, token and profile storage: `backend/.../Application.kt`, `Database.kt`,
  and migrations V1. Recovery email is generated by `SmtpPasswordResetDelivery.kt`.
- Account deletion: `backend/.../nearby/JdbcAccountDeletionRepository.kt`.
  Email/password hash/display name are replaced; auth token, friendship, current
  sharing and push-device records are removed. UUID tombstones and operational
  journals remain; no general timed purge was found. This is not described as
  immediate erasure of every server row.
- Live-sharing packet content, precision and TTL: `ChannelSharingCaptureOwner.kt`,
  `domain/nearby/ChannelSharing.kt`, `domain/social/SocialPolicies.kt`,
  `ChannelSharingPacket.kt` and server `JdbcChannelSharing*`. Sample freshness is
  distinguished from physical deletion/retention; no unsupported deletion deadline
  was inferred from the UI's freshness timeouts.
- Voice: `AndroidVoiceSdkSession.kt` and `OwnedVoiceAudio.kt` publish live audio
  to LiveKit; no application E2EE setup or persistent PCM recording was found.
  Policy does not promise that other participants cannot record a conversation.
- Wi-Fi Direct radio: `RadioKeyHttpPort.kt`, `RadioCredentials.kt`,
  `RadioUdpTransport.kt`, `RadioPacket.kt`, `RadioHubSession.kt`. Audio and identity
  metadata use local group-key encryption; this is not described as endpoint-only
  E2EE, nor as a source of location-sharing packets.
- Push: `PushRegistrationOwner.kt`, server `JdbcPushDeviceRegistry.kt` and
  `HttpFcmSender.kt`. FCM payload carries call/binding/revision identifiers,
  not audio, coordinates or telemetry.

## Operator and infrastructure facts

On 2026-10-29 the operator explicitly confirmed that server database backups are
not retained. This is separate from Android's system backup behavior.
The server's `/etc/logrotate.d/nginx` specifies daily rotation and `rotate 14`;
the policy describes 14 archives, not an unconditional 14-calendar-day purge.
The application container uses Docker's json-file logger without configured
rotation options; no application-level log TTL is stated in source.

The pre-existing account-removal page contains a generic sentence saying that
earlier server backups are not changed by deletion. Its wording should be aligned
with the operator's no-backups practice in a separate backend page update; this
privacy-page edit does not change the account-deletion API or its behavior.
