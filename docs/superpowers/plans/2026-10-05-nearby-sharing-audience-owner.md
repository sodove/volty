# Original-session sharing audience owner

Create an original account/session/channel-bound root owner borrowing the proven sharing
control. Validate exact identity before allocating a unique root child; never close borrowed
voice/authentication/sharing control. Root-owned coalesced audience reads survive UI waiter
cancellation. Account retirement/current voice capability loss clears data and closes this
owner. A finite tick loop removes each expired peer even without another successful request.

Projection keeps request ordinal, rejects stale replies, and never renews a repeated exact
packet's previous conservative monotonic deadline. Same-generation lower sequence or conflicting
equal-sequence payload cannot replace earned coordinates. Local own-generation withdrawal
filters own packet. Empty sharing audience remains valid and says nothing about voice count.
Transient read failure retains only still-fresh data; authorization denial retires the owner.

Use the actual existing voice HTTP fixture. Tests first: cancelled UI waiter/coalesced held
read, local clock expiry without HTTP, authorization denial/disconnect cleanup, old account
late reply across new same-user login, exact borrowed-control mismatch before allocation.
