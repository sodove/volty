## 2. Доставка Crashlytics

AAB 0.7.71 содержит FirebaseInitProvider, CrashlyticsRegistrar, app ID и mapping. Лог показывает пять падений, следующий запуск и connection closed у Firebase Sessions. Ответа сервера на отправку краша в логе нет. Маппинг R8 из AAB содержит обработчик необработанных исключений, сериализатор отчёта, очередь и CCT-транспорт. Имя CrashlyticsRegistrar сохранено. Проверка наличия классов не проверяет их поведение при отправке.

- [ ] На эмуляторе с сетью включить adb shell setprop log.tag.FirebaseCrashlytics DEBUG. На локальной подписанной сборке с конфигурацией того же Firebase-приложения вызвать один явно помеченный тестовый fatal, перезапустить и записать лог FirebaseCrashlytics и транспорта.
- [ ] Проверить upload complete или HTTP 204 и появление тестового события в консоли. Если отправка не проходит, исправить подтверждённый сбой и повторить прогон. Тестовый триггер держать в локальном диагностическом патче.
- [ ] При успешном локальном прогоне сопоставить логи SDK с Nothing A024 после перезапуска. Ошибка запроса Firebase Sessions сама по себе не локализует сбой отправки краша.

### Фоновая конвертация

- [ ] Перенести правила кодирования из 28.sqm в порционный конвертер. Идти по индексированному курсору, ограничивать размер транзакции даже для одной очень длинной поездки. Сохранять позицию и состояние незакрытого интервала неизвестных значений атомарно с данными порции.
- [ ] Публиковать компактный ключ поездки только после завершения её конвертации. До публикации исходные строки остаются источником истины. Удаление поездки и сборка мусора должны учитывать обе версии данных. Проверить гонки с новой записью, экспортом и удалением.

### Запуск и прогресс

Для фоновой работы использовать уникальную задачу WorkManager. Каждый запуск обрабатывает ограниченный объём и сохраняет контрольную точку. Прерывание процесса и отмена задачи оставляют последнюю завершённую порцию. При явной паузе не планировать следующую задачу. Проверить уход в фон, повторное планирование и паузу на API 26 и современных Android.

- [ ] Открывать основные экраны после короткой подготовки схемы. Для незавершённых поездок показывать статус переноса в истории, для готовых и новых сохранять обычные операции.
- [ ] На первом старте объяснить, что переносится. После прерывания предложить «Продолжить» и «Позже». Добавить русский и английский текст. Показать только подтверждённый прогресс, по обработанным порциям и числу завершённых поездок. Если общий объём ещё неизвестен, показать этап без процентов.
- [ ] Измерить время до первого доступного экрана, пик места и время возобновления на копии 6 ГБ или сопоставимой синтетической базе. Проверить, что после принудительной остановки возобновляется работа с последней подтверждённой порции.
