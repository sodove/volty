# Original incoming notification actions

Consume only this owner's current opaque ticket while its original ring observation is fresh.
Withdraw notification first and fence pending publication; duplicate/expired/foreign/stale
tickets perform no HTTP. Acceptance resolves fresh status again and returns only metadata for
explicit visible-Activity startup; it cannot allocate foreground or media. A newer hint or
account retirement during recheck invalidates the action. Actual accept is still server revision
checked by the existing root.

Decline uses the original already-observed ring snapshot and a fresh validated operation,
submits to the runtime's original cleanup-root Deferred, and returns only a waiter. After
submission, UI cancellation or notification owner close cannot abort this original negative
request. Acceptance racing decline returns actual conflict, never implicit accepted-call stop.
Tests actual HTTP, original ticket once, duplicate/newticket guard, explicit startup after
fresh resolution and held negative cleanup across UI/logout. Android PendingIntent resolution
and notification port follow; no background microphone/FCM provisioning.
