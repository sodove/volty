# Root-owned incoming notification acquisition

Cache one notification attachment per exact captured account and actual borrowed runtime.
Require runtime/account identity, active original application root and queued serial dispatcher
before replacement. Root owns builder Deferred; cancelling UI/push waiter cannot cancel or
lose created attachment. No automatic hint, HTTP, foreground or SDK allocation at acquire.

Capture predecessors at selection, close their unique notification children before build,
and retire obsolete late results using their original binding identity. Never sample newer
entries from an older builder; never retire a borrowed audio runtime/account. Factory returns
a unique owned attachment; validate actual owner/account and registry binding before reuse.
Account cancellation already closes its reader; late factory after logout cannot rebind new
account. Explicit retireAll fences builders without joining held work.

Move attachment/factory contract to common; Android factory implements it, lazy Koin provides
coordinator. Actual HTTP tests cover cached root builder and cancelled waiter, deliberately
held old factory across same-user new account, and wrong account/runtime rejection before
current notification replacement. Finite gates and exact fresh Android suite before commit.
Manual parent review only; no FCM provisioning/UI/backend/native acceptance claim.
