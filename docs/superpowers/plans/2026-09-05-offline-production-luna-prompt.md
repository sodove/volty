# Стартовый промпт для GPT-5.6 Luna

Модель задачи: **gpt-5.6-luna**. Рекомендуемое усилие рассуждения: **high**.
Запускать в текущем worktree Volty со всеми существующими изменениями.
Этот файл сам не запускает агента и не создаёт deployment.

Скопировать следующий текст в задачу Luna:

---

Реализуй и доведи до фактически работающего production следующий план целиком:

- `docs/superpowers/plans/2026-09-05-offline-production-luna.md`
- `docs/superpowers/specs/2026-09-05-offline-production-design.md`

Сначала прочитай AGENTS.md, оба документа, текущие изменения и ledger
`.superpowers/sdd/2026-09-05-offline-production-luna/progress.md`, если он существует.
Работай с фактическим текущим worktree: main устарел, пользовательские
незакоммиченные изменения нельзя потерять, отменить или незаметно исключить из сборки.

Production уже существует. SSH: `ssh -p 22 sodovaya@mc.sodove.ru`.
Пользователь требует выполнять сборку карт на этом же VPS. Backend, registry,
publisher, storage, worker и scheduler должны работать там постоянно.
Homeserver 192.168.1.141 разрешён только для тестов, не используй его как
production builder. Сначала установи реальные deployment paths, сервисы,
ресурсы и доверенные ключи. Не печатай секреты. До изменений сохрани backups.

Цель включает реальное развёртывание backend, автоматическое получение исходных
OSM данных, сборку и публикацию всего принятого покрытия России, зарубежную
генерацию по запросу приложения, обновления сервера и карт клиента, подписанный
production APK и проверку native offline сценариев на emulator.
Не заканчивай на написанном коде, пустом каталоге, unit-тестах или поставленной
в очередь генерации. Готовность доказывается финальными gates плана.

Используй superpowers:subagent-driven-development по AGENTS: отдельный implementer
на задачу, review и исправления. Для исполнения используй выбранную пользователем
модель Luna. Передавай каждому implementer конкретные файлы и контракты; предупреждай,
что в worktree есть чужие изменения. Веди один ledger с реальными проверками и
результатами; не считай старый ledger package delivery завершением этого плана.

Тяжёлые сборки выполняй по одной, с cgroup лимитами, дисковым admission и резервом
для живых API/DB/voice. До полной России измерь реальные пилоты и ёмкость хранения
двух версий, sources и staging. Не покупай ресурсы, не переноси сборку на другую
машину и не рискуй OOM production при нехватке памяти. Если ресурсов объективно
недостаточно, зафиксируй измеренный blocker и продолжай независимую работу;
результат с незакрытым blocker называй незавершённым.

Не запрашивай повторное разрешение на уже входящие в эту задачу реализацию,
генерацию данных и deployment. Уточнение требуется при реальном отсутствии
доступа, необходимости новых расходов или конфликте ключей/инфраструктуры,
который нельзя разрешить в утверждённом объёме. Не удаляй действующие volumes,
не запускай глобальный prune, не затрагивай физический телефон или BLE FFE1.

Исправления подписи, source coverage и производительности подтверждай фактами.
Не подменяй routing policy generic costing, не фабрикуй данные пустых регионов,
не отключай checksum/signature и не выдавай mock routing за native smoke.
Автообновления должны работать в постоянных production-службах после завершения
задачи Codex, а не зависеть от активного агента.

В конце предоставь реальные API/catalog/APK адреса, coverage/source-age отчёт,
результаты четырёх зарубежных cold builds, offline native проверки, update/rollback,
restore, измерения ресурсов и краткую инструкцию эксплуатации. Если какой-либо
обязательный gate не выполнен, укажи это явно и не заявляй «production полностью готов».
