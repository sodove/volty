# Благодарности и лицензии — дизайн

Дата: 2026-10-29. Статус: дизайн согласован с поправкой ниже; зависимости и
продуктовый код пока не менялись. Пользователь уточнил: подробно расписывать вклад
не требуется, особые благодарности и любое визуальное выделение проектов не нужны.

## Решение

Отдельная страница **«Благодарности и лицензии»** в группе **«Приложение»**
на текущем экране настроек, рядом с картами и темой. Подпись строки:
«Проекты, на которых построен Volty». Иконка HeartHandshake или ближайшая
доступная иконка Material; не добавлять набор иконок ради одной строки.

Страница использует текущую Material 3 Expressive тему, системные динамические
цвета, типографику и обычную стрелку назад. Возврат ведёт в настройки; из
карточки проекта — в каталог с сохранением поиска и позиции списка.

- Короткое вступление: «За Volty стоит работа многих людей. Спасибо тем, кто
  делится своим кодом».
- Поиск по названию, авторам и названию лицензии. Пустой результат:
  «Ничего не найдено». Пустой запрос возвращает весь каталог.
- Один алфавитный список всех проектов с одинаковым оформлением строк, включая
  Vescape и loeuc-core. Без закрепления, специальных карточек, рейтинга и отдельных
  благодарностей. Название, короткая подпись при наличии, версия и лицензии.
  Без перечней функций, патчей, файлов и истории изменений.
- Открытие записи показывает имя проекта, авторов, одну короткую подпись,
  версию при наличии, ссылку на исходный проект и действие «Читать лицензию».
  Полные тексты и обязательные уведомления доступны локально без интернета,
  сохраняются на языке оригинала. При нескольких лицензиях доступны все;
  выражения SPDX AND/OR не заменяются произвольным выбором одной лицензии.
- Не выводить SHA, координаты Maven и технические сведения сборщика в основном
  списке. Не выводить надпись о «юридической проверке»: такой вывод не сделан.

Минимальные редакционные записи:

| Проект | Автор | Подпись | Лицензия |
|---|---|---|---|
| Vescape | Kacper Kozak и участники проекта | Интерфейс истории поездок | GPL-3.0-or-later |
| loeuc-core | Nikita Vasilevskiy | Телеметрия моноколёс | MIT |
| RNNoise | Jean-Marc Valin и участники проекта | Шумоподавление микрофона | BSD-3-Clause, с исходными уведомлениями |

Все правообладатели RNNoise остаются в полном COPYING; короткая подпись автора
на экране его не заменяет. Лицензию загружаемой модели RNNoise проверить отдельно
от лицензии C-кода при подготовке полного реестра.

Макет показывает несколько существующих компонентов для проверки интерфейса;
это не результат нового полного сканирования зависимостей.

## Сборщики: что подходит

| Инструмент | Роль | Вывод для Volty |
|---|---|---|
| [AboutLibraries](https://github.com/mikepenz/AboutLibraries) | Генерация сведений о Gradle-зависимостях и лицензиях; KMP; ручные дополнения; данные для своего UI | Основной кандидат. Использовать генератор, экран отрисовать в теме Volty. |
| [Licensee](https://github.com/cashapp/licensee) | Проверка dependency graph и JSON-отчёт о лицензиях | Полезен для CI при отдельной необходимости; для первой версии не нужен второй сборщик. |
| [Google OSS Licenses](https://developers.google.com/android/guides/opensource) | Android plugin и готовая Activity лицензий | Рабочая альтернатива для Android, но хуже подходит нашему собственному KMP-экрану. |

У AboutLibraries есть ручной реестр в `configPath/libraries` и `licenses`;
поэтому перенесённый напрямую код можно включить явно, не создавая фиктивные
Maven-зависимости. Нативные вложенные компоненты автоматически полностью не
обнаруживаются: нужен дополнительный реестр и проверка состава релиза.

## Предлагаемая интеграция

1. Генерация из **разрешённого release runtime graph**, включая транзитивные
   зависимости. Не представлять version catalog и старый список POM как полный
   реестр: текущий `ride-history-runtime-licenses.md` снят с 0.7.28.
2. Версионируемый ручной реестр для Vescape, loeuc, собственного нативного
   включения RNNoise, локальных JAR/AAR, вложенного native-кода, данных и ресурсов.
   Служебные поля источника/ревизии/локальных notices хранятся здесь, без подробного
   рассказа пользователю. Наличие импортированной Gradle-библиотеки не обязательно.
3. Объединение по стабильному ID, проверка дубликатов и обязательных текстов;
   генерация одного компактного каталога и локальных license/notice ресурсов.
   Один источник данных должен кормить экран и экспортируемые notices, чтобы
   они не расходились. Существующие THIRD_PARTY_NOTICES и лицензии не удалять.
4. Результат привязан к релизу. Либо автоматическая release-задача, либо проверка
   актуальности snapshot на release/CI; не разрешать тихо упаковать старый каталог.
   Не искать лицензии в сети при открытии экрана. Новые нераспознанные компоненты
   должны давать диагностический отчёт сборки, а не автоматически получать MIT.
5. AboutLibraries используется как Gradle-инструмент; для UI необязательно
   подключать его Compose-компоненты. Преобразовать данные в небольшую модель
   Volty существующим kotlinx.serialization; это ограничивает влияние чужой UI
   версии на приложение. Финальный выбор plugin/core проверить сборкой.

Текущий стек: Kotlin 2.3.20, Compose Multiplatform 1.11.0, AGP 8.13.2.
У AboutLibraries актуальная опубликованная ветка 15.x имеет другой стек
зависимостей; нельзя автоматически подтягивать её UI вместе с обновлением AGP.
13.2.1 — кандидат для отдельной проверки генератора на нашем стеке, а не уже
проверенная совместимая версия. Обновление Kotlin/AGP/Compose в эту задачу не входит.
Лимиты Gradle: workers=4 и ActiveProcessorCount=4 сохраняются.

Backend можно инвентаризировать отдельным отчётом для серверного дистрибутива.
Его зависимости не смешиваются с перечнем того, что поставляется внутри APK.
Карты, шрифты, стили и внешние источники данных учитываются вручную там, где
используются; новый экран не заменяет существующую атрибуцию на карте.

## Реализация экрана и проверки

Расширить текущий SettingsPage/SettingsPageNavigator пунктом CREDITS. Добавить
вложенное состояние credits: каталог / выбранный проект / текст лицензии.
Toolbar и системный Back сначала закрывают текст лицензии, затем проект, затем
CREDITS; существующий одноуровневый navigator сам этого не делает. Поиск и
позиция каталога переживают эти переходы. Данные и переходы держать в
компоненте/чистой модели; Compose отображает состояние и передаёт действия.

Список — LazyColumn с собственным ограниченным по высоте корнем. Сейчас все
settings pages обёрнуты в Column.verticalScroll: CREDITS нужно вывести из этой
общей обёртки, иначе вложенный LazyColumn получит бесконечную высоту. У подробностей
и полного текста — собственная прокрутка без вложенных вертикальных скроллов.
Тексты выбираемы, имена
проектов и лицензии не переводятся. Строки UI — values и values-ru. В Expanded
допустимы список и подробности в двух панелях; Compact — последовательные страницы.

Проверить модель с отсутствующим автором/версией, несколькими лицензиями,
совпадающими названиями, длинными именами, большим полным текстом; поисковые
состояния и возврат. Проверить release-каталог на включение Vescape/loeuc/RNNoise,
локальные тексты и отсутствие тестовых зависимостей. Визуально: светлая/тёмная
тема, 320/390/840 dp, крупный системный шрифт, TalkBack и офлайн-режим. Compose
проверяется на устройстве: в этом репозитории нет Compose UI test infrastructure.

Builder-check выявил обе особенности текущей интеграции (общую scroll-обёртку
и одноуровневый Back); решения выше включены в дизайн. Недостающие обязательные
license/notice тексты — ошибка генерации, не заглушка в релизном UI.

Повторный builder-check подтвердил устранение замечаний. Интерактивный макет
проверен в браузере: поиск и пустой результат, последовательный Back, сохранение
запроса, полные GPL/MIT/RNNoise тексты, светлая/тёмная тема и отсутствие
горизонтального переполнения при 320/390/760 px. Это проверка макета, не
инструментальный тест Android-экрана и не запуск сборщика лицензий.
