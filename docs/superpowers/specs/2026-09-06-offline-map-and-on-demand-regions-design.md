# Офлайн-карта и регионы по запросу — спецификация

## Цель

Сделать офлайн-навигацию пригодной для релизного APK:

- после загрузки региона маршрутизация, поиск и карта работают без сети;
- на дальнем масштабе карта не превращается в плотное облако линий и не становится пустой за пределами скачанного региона;
- в настройках можно найти и скачать любой регион из поддерживаемого каталога;
- сборка регионов запускается только явным запросом пользователя или оператора. Планировщик массовой публикации не включается;
- Екатеринбург остаётся готовым примером, а подпись каталога и APK-ключ не меняются.

## Ограничения и совместимость

Публичный каталог остаётся единственным доверенным источником метаданных и по-прежнему подписывается Ed25519. Формат сохраняет `schemaVersion = 2`, но Android-модель дополняется полем `onDemand`, чтобы старые готовые записи и новые записи без релиза проходили одну проверку. Приватный ключ не попадает в APK и не монтируется в приложение.

Запись каталога имеет вид:

```json
{
  "region": { "regionId": "g1-146-240", "displayName": "Екатеринбург", "bounds": { "south": 56, "west": 60, "north": 57, "east": 61 } },
  "latestRelease": null,
  "onDemand": { "enabled": true }
}
```

Для опубликованного региона `latestRelease` содержит существующий подписанный manifest. Для поддерживаемого, но ещё не собранного региона он равен `null`; это не ошибка каталога, если `onDemand.enabled = true`.

## Поток загрузки региона

1. Сервер публикует подписанный каталог со всеми поддерживаемыми регионами. Записи сортируются по названию и ID; у каждой записи есть автоматически извлечённое из OSM человекочитаемое имя. Ранее здесь был описан fallback с координатами; полевой просмотр отверг его как непригодный для UI. Теперь имя выбирается из населённого пункта в логическом bbox, а при отсутствии такого объекта используется имя исходного административного extract-а.
2. Настройки показывают установленные и активные регионы сверху. Пустой поиск не рендерит тысячи ячеек: показываются установленные и небольшой список подсказок. Поиск по названию или ID раскрывает совпадения.
3. При нажатии «Скачать» для записи с готовым релизом сохраняется текущий поток `ensure → проверка manifest → скачивание по checksum → атомарная установка`.
4. Для записи с `latestRelease = null` приложение отправляет `POST /offline/regions/{id}/ensure` без версии. Сервис проверяет ID в production-конфигурации, создаёт идемпотентную заявку и возвращает `queued`/`building` с `requestId`. Повторное нажатие не создаёт второй job.
5. Внутренний endpoint worker-а доступен только в Compose-сети. Он атомарно добавляет заявку в существующую очередь. Worker использует уже имеющийся source cache и pipeline, собирает routing/search/PMTiles, подписывает manifest и публикует неизменяемый релиз.
6. После публикации worker пересобирает каталог, включая и ещё не собранные `onDemand`-регионы. Приложение опрашивает status с backoff, обновляет каталог и запускает обычную checksum-проверенную загрузку. При ошибке отображаются «Повторить» и причина; частичная загрузка удаляется безопасно.

Публичные статусы: `queued`, `building`, `ready`, `unavailable`, `failed`. Запрос с явным `releaseVersion` сохраняет совместимость с уже опубликованными пакетами. Scheduler остаётся в compose-файле только как явно не запускаемый профиль и не участвует в штатном запуске.

## Карта и масштабирование

В APK добавляется небольшой упрощённый world-overview слой: фон, суша/вода, границы/подписи крупных стран и несколько крупных городов. Он не зависит от скачанных PMTiles и служит только для дальнего масштаба, поэтому при отключённой сети видны мир и территории вне локального пакета.

Региональный MapLibre-стиль делится по zoom:

- `z < 8`: только фон, вода, суша, крупные дороги и города;
- `8 ≤ z < 12`: магистрали и отобранные улицы, разреженные подписи;
- `z ≥ 12`: локальные улицы, подписи и POI;
- 3D-здания включаются только на близком масштабе (`z ≥ 13`) и получают высоту из `height`, `building:levels` и `min_height` с безопасным default, чтобы не пропадать и не перегружать дальний вид.

Для дорог используются фильтры по классу и отдельные minzoom; POI и подписи не рисуются на дальних уровнях. Наклон камеры ограничивается на дальнем масштабе, а world-overview не смешивается с подробными региональными слоями.

Локальный PMTiles HTTP-сервер игнорирует отмену запроса MapLibre: `BrokenPipeException`, `ConnectionResetException` и аналогичные ошибки закрытого клиента считаются нормальным завершением запроса и не могут уронить процесс.

После построения маршрута preview-камера принудительно сбрасывает наклон и азимут перед fit bounds и учитывает только актуальную область карты под верхней панелью и карточкой маршрута. Повторная прокладка маршрута получает новую последовательность camera request, поэтому старый fit не блокирует новый.

Поиск очищается в два слоя. При построении FTS-индекса одинаковые OSM-объекты и одинаковые названия в одной точке объединяются, при этом сохраняется наиболее полезный тип объекта. На клиенте остаётся защитная дедупликация по нормализованному названию и координатной близости; отдельные филиалы с одинаковым названием на заметном расстоянии не склеиваются. В выдачу не попадают технические строки вроде `amenity:food_court`, если можно показать нормальную категорию или адрес.

## Ошибки и безопасность

- неизвестный регион — `404 unavailable`, без постановки произвольного job;
- отсутствующая исходная выгрузка или ошибка сборки — `failed` с безопасным кодом, без раскрытия путей и ключей;
- каталог с null-релизами валиден только для `onDemand`-записей;
- публикация релиза и каталога атомарна, существующий релиз неизменяем;
- API сборки не публикуется наружу и не получает доступ к приватному ключу из приложения;
- при отсутствии сети приложение сохраняет world-overview и установленные пакеты, но не пытается строить или скачивать регион.

## Проверка результата

Будут добавлены тесты для каталога с готовым и on-demand регионом, идемпотентности заявки, переходов статуса, поиска/фильтрации настроек, дедупликации индекса и camera fit. На эмуляторе проверяются три диапазона zoom, наличие world-overview за пределами Екатеринбурга, 3D-здания вблизи, скачивание второго региона после подготовки и запуск навигации в авиарежиме. Отдельно проверяется построение маршрута после ручного zoom/tilt и повторное построение другого маршрута. Logcat проверяется на отсутствие `FATAL EXCEPTION` в сценариях панорамирования, зума и отмены тайловых запросов.
