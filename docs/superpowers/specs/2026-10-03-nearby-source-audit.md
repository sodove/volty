**PHONE → Speakerphone сейчас:** `AndroidLiveKitVoiceRoomEngine.applyMicrophoneSource` ставит Speakerphone первым в `room.audioSwitchHandler.preferredDeviceList`. Handler пересылает list через свой HandlerThread в local AAR `AbstractAudioSwitch.setPreferredDeviceList` → `selectAudioDevice` → `activate/onActivate`. API31+ выбирается **communication output** Speakerphone; API26–30 выключается SCO и включается speakerphone. Ни текущий product method, ни этот call chain не вызывает `JavaAudioDeviceModule.setPreferredInputDevice`. Поэтому утверждение «PHONE означает отдельный phone microphone с сохранением headphones output» неверно на уровне текущего кода; actual route устройства всё равно требует измерения.

**Существенная несовместимость документации:** SDK 2.25.3 `selectDevice` комментирует sticky selection после hot-plug. Local AAR `CommDeviceAudioSwitch.onDeviceDisconnected` явно обнуляет `userSelectedAudioDevice`, если он совпадает с удалённым device. Нельзя переносить гарантию SDK-комментария на этот AAR; следующий controller хранит желаемый маршрут самостоятельно и проверяет события/actual state.

**Ограниченный prototype boundary:** сначала один custom AudioHandler + существующий Java ADM input preference, без правок AAR/versions; measured route может оставаться Unknown. Для строгого per-stream input/output control и callback нужен отдельно спроектированный custom ADM/адаптер с собственными Android AudioRecord/AudioTrack и native ADM integration. Внешний interface ADM (`getNative(long)`, release, mute) сам по себе не является turnkey Kotlin factory. Собственный capture через `LocalAudioTrack.setAudioBufferCallback` + Java ADM `setAudioRecordEnabled(false)` — supported PCM boundary, но ещё не доказанная полная замена duplex/audio lifecycle. Нельзя обещать split routing Bluetooth/phone только на основании этих hooks.

## Reconnect и mute ownership

[RTCEngine.kt](https://github.com/livekit/client-sdk-android/blob/701d548f09d969eed689ecac5c039afd3fe9455a/livekit-android-sdk/src/main/java/io/livekit/android/room/RTCEngine.kt), `reconnect`, `connectionState`, `onRefreshToken`; Room `onEngineReconnecting/onEngineReconnected/onFullReconnecting/onPostReconnect`; [LocalParticipant.kt](https://github.com/livekit/client-sdk-android/blob/701d548f09d969eed689ecac5c039afd3fe9455a/livekit-android-sdk/src/main/java/io/livekit/android/room/participant/LocalParticipant.kt), `setMicrophoneEnabled/setTrackEnabled/prepareForFullReconnect/republishTracks`; [LocalTrackPublication.kt](https://github.com/livekit/client-sdk-android/blob/701d548f09d969eed689ecac5c039afd3fe9455a/livekit-android-sdk/src/main/java/io/livekit/android/room/track/LocalTrackPublication.kt), `muted`:

- SDK владеет reconnect существующей Room: первый обычный retry soft, последующие full; policy и caps (30 attempts, elapsed check 60s) внутри SDK. Controller не запускает параллельный connect-loop; session generation должен отвергать старые события и прекращать Room при revoke/lease expiry.
- Full reconnect закрывает transport resources, вызывает `prepareForFullReconnect` (сохраняет publications, очищает map), join, затем при transport convergence `onPostReconnect` и republish **только unmuted tracks**. Muted publication после full reconnect не автоматически republished.
- RoomEvent.Reconnected рождается при transition primary ICE to CONNECTED; republish делается отдельным `onPostReconnect` позже. Reconnected не доказывает microphone publication/capture/duplex. Soft resume hooks по умолчанию не преобразуются в те же RoomEvents (listener defaults пустые); нельзя строить полноту диагностики только по Reconnecting/Reconnected.
- `setMicrophoneEnabled(true)` создаёт default track, prewarm/start и publish при отсутствии publication, либо unmute существующую; возвращает Boolean success. `false` mutates publication.muted; отсутствие publication также success. Publication setter меняет WebRTC track enabled и отправляет updateMuteStatus. Это не shutdown Android AudioRecord: prewarming и record ресурсы имеют отдельный lifecycle. Product `setMuted` сейчас игнорирует Boolean return, успешный Result<Unit> не доказывает SDK success.
- Controller владеет желаемым mute и повторно сверяет publication state после full reconnect; SDK владеет actual track enable/publish. Room ADM-level `setMicrophoneMute`/`setSpeakerMute` — отдельные controls, не замена publication state.
- SignalClient REFRESH_TOKEN → RTCEngine.onRefreshToken обновляет private sessionToken/region token; reconnect использует его. App-issued expiration не ограничивает этот новый credential. Product connect URL/token в старом controller не являются полным списком credentials клиента.
